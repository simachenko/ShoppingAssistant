# Quickstart: Store Info RAG

This guide proves the feature works end-to-end locally, on top of an already-running
`001-smart-product-advisor` stack (see that feature's `quickstart.md` for base prerequisites and
how to start the stack — .NET Aspire or `docker compose up --build`). This guide does not contain
implementation code — see `tasks.md` (generated by `/speckit-tasks`) for build-out steps, and
`data-model.md` / `contracts/` for the shapes referenced below.

## Additional prerequisites (beyond 001's quickstart)

- The Advisor's Postgres schema has the `pgvector` extension enabled (`CREATE EXTENSION IF NOT
  EXISTS vector;` — applied by an EF Core migration, research.md §2).
- The configured LLM provider's embedding endpoint/key is set (same provider config as the chat
  client — research.md §3); no separate credential is required if using the same OpenAI-compatible
  provider already configured for chat.
- At least one seeded `Store` row exists (the demo/default store — data-model.md `Store`).

## Seed a store document

Using the internal ingestion API (`contracts/advisor-mcp-tools-additions.md`), directly against
the Advisor container (never through the Gateway):

```bash
curl -X POST http://localhost:5103/api/store-documents \
  -H "X-Internal-Api-Key: dev-internal-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "slug": "returns-policy-main-en",
    "storeCode": "main",
    "documentType": "returns",
    "language": "en",
    "title": "Return Policy",
    "sourceLabel": "store-policies/returns-en.md",
    "content": "Items may be returned within 14 days of delivery if unused and in original packaging. Opened electronics may be returned within 7 days for a refund, provided all accessories and packaging are included. Refunds are issued to the original payment method within 5 business days of the item being received."
  }'
```

**Expect**: `200` with `{ "documentId": "...", "chunkCount": <n>, "status": "active" }`, `n >= 1`.

## Validation Scenario 1 — Grounded, cited answer (US1, SC-001, SC-003)

1. Open the Blazor app and start a new chat (or continue an existing signed-in session).
2. Send: `Can I return a product I already opened?`
3. **Expect**: a `storeInfo` response (`contracts/advisor-conversation-api-additions.md`) whose
   `message` is consistent with the seeded content above (mentions the 7-day opened-item window)
   and whose `citations` array is non-empty, referencing the "Return Policy" document.

## Validation Scenario 2 — Honest "not enough information" (US1 Scenario 2, SC-002, edge case)

1. In the same or a new chat, send: `Do you have a loyalty program?`
2. **Expect** (no loyalty document has been seeded): a `storeInfo` response whose `message` states
   it does not have enough information to answer, and whose `citations` array is `[]` — never a
   guessed answer, never a fabricated citation.

## Validation Scenario 3 — Store policy never leaks into product facts, and vice versa (US2, SC-003, SC-006)

1. Send: `What's the price of the Galaxy S24?` (assuming this product is seeded per 001's own
   quickstart data). **Expect**: an `answer`/`recommendation`-shaped response as usual, with no
   `citations` field present.
2. Send: `What's your return policy?` **Expect**: a `storeInfo` response as in Scenario 1, with no
   product-catalog/pricing tool having been invoked (verifiable via traces in the Aspire dashboard
   — no `Catalog`/`Pricing` span for this turn).
3. Send: `Is the Galaxy S24 in stock, and what's your return window?` **Expect**: an `answer`
   response with `fact` populated from the real stock status (verified via the Pricing/Catalog
   tools) **and** a non-empty `citations` array grounding the return-window portion of `message` —
   both parts answered correctly in one response (spec.md US2 Acceptance Scenario 3).

## Validation Scenario 4 — Updated content is reflected without a redeploy (US3, SC-005)

1. Re-run the `POST /api/store-documents` request above with the same `slug` but a changed
   `content` (e.g., change "7 days" to "10 days").
2. Repeat Scenario 1's question. **Expect**: the new answer reflects "10 days," with no service
   restart or redeploy performed between steps 1 and 2.

## Validation Scenario 5 — Withdrawal removes a document from future answers (US3 Scenario 2)

1. `DELETE http://localhost:5103/api/store-documents/{documentId}` (the id returned when the
   document was created), with the same `X-Internal-Api-Key` header. **Expect**: `204`.
2. Repeat Scenario 1's question. **Expect**: a `storeInfo` response with `citations: []` and the
   fixed "not enough information" message (assuming no other document covers returns) — the
   withdrawn document is never retrieved or cited again.
